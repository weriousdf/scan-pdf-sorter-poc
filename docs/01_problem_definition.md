# 문제 정의서 — 스캔 PDF 페이지 분류 자동화 PoC

작성일: 2026-09-24 · 작성자: 김보겸

---

## 1. 도메인 설명

글로벌 문서 대행(번역·공증·아포스티유·대사관 인증) 업무. 업무가 끝난 서류는 스캔 PDF 로 남는데,
이것을 **블로그 홍보 포스팅의 자료 이미지**로 다시 쓴다. 이 과정은 고객 업무와 별개로 내가 따로 하는 작업이다.

하나의 PDF 에는 여러 종류의 서류가 섞여 있다.

- 세로 A4 서류: 번역 인증서, 재학·입학증명서, 번역 확인서 등
- 가로 A4 서류: 졸업장처럼 원래 가로로 만들어진 서류
- **A4 위에 올려 스캔한 작은 서류**: 여권, 신분증, 작은 아포스티유 등. 페이지 크기는 A4 지만 내용은 작은 종이 한 장이다
- 가끔 페이지 자체가 A5 로 저장된 것

## 2. 현재의 문제

지금은 PDF 를 열어 페이지마다 눈으로 보고, **세로는 세로대로, 가로는 가로대로, 작은 서류는 따로** JPG 로 저장한다.
14쪽짜리 PDF 하나에 **약 2분**이 걸린다.

이 작업을 "세로 A4 기준" 같은 한 가지 틀로 자동화하면 가로 서류가 잘려서 저장된다. 그래서 페이지마다
어떤 모양의 서류인지를 먼저 구분해야 한다.

## 3. 개선 가설

**가로/세로 구분은 AI 가 필요 없다.** PDF 페이지는 자기 크기를 숫자로 갖고 있어서, 가로가 세로보다 길면 가로다.

**AI 가 필요한 것은 "A4 서류인가, A4 위에 놓인 작은 서류인가" 구분이다.**
흰 종이를 흰 스캐너에 올리면 종이의 경계가 보이지 않는다. 그래서 규칙은 종이 크기를 잴 수 없고 글자가 있는
영역만 잴 수 있는데, **내용이 위쪽에만 있는 A4 서류(증명서 뒷장, 표 하나짜리 번역본)와 A4 위의 작은 서류는
글자 영역 크기가 같다.** 사람은 한눈에 가르는 이 차이를 이미지를 이해하는 모델이 가를 수 있을 것이다.

> **가설** — 이미지-텍스트 모델(CLIP)로 "A4 서류 / 작은 서류"를 판단하면, 글자 영역 크기 규칙보다 정확하고,
> 페이지를 JPG 로 떼어 폴더별로 나누는 작업을 사람 손 없이 할 수 있다.

## 4. 정답 판정 규칙

- **R1. 종이 크기 기준이다.** 글자 영역이 아니라 종이의 가로·세로가 각각 페이지의 **95% 이상이면 A4 서류**다.
  A4 경계가 애매한 경우(A4 위 거의 A4 크기 종이)는 A4 로 본다. 접힌 자국·약간의 기울어짐은 따지지 않는다.
- **R2. 회색 배경 위에서 찍은 서류 사진**은 종이가 페이지의 대부분을 차지하면 A4 서류다.
- **R3. 페이지가 A4 보다 작으면(A5 등)** 작은 서류이며, 크기를 바꾸지 않고 그대로 저장한다.
- **R4. 저장은 페이지 직사각형 그대로** 한다. 작은 서류도 잘라내지 않고 A4 페이지째 저장하고, 폴더로만 구분한다.

정답표는 모델을 돌리기 전에 확정했다: 가짜 샘플은 [`data/ground_truth.csv`](../data/ground_truth.csv),
실제 서류는 비공개 폴더에 따로 둔다.

## 5. 대상 사용자

- **1순위: 나.** 블로그 포스팅용 서류 이미지를 정리하는 문서 대행 블로그 작성자
- **2순위:** 스캔 서류를 페이지별 이미지로 정리해야 하는 번역·행정 사무소 실무자

## 6. 성공 기준

> **A. 정확도** — 페이지를 올바른 폴더(A4/작은 서류 × 가로/세로)에 넣는 비율이 **90% 이상**.
> 내가 최종 검수를 하므로 100% 가 아니어도 되지만, 90% 는 넘어야 검수가 수월하다.
>
> **B. 작은 서류를 놓치지 않는다** — 작은 서류는 "전부 A4 로 분류"만 해도 전체 정확도가 높게 나올 수 있다
> (실제 서류에는 작은 서류가 적다). 그래서 작은 서류를 몇 장 잡아냈는지를 따로 본다.
>
> **C. 시간** — 수작업(14쪽 약 2분)보다 빨라야 한다.

A 의 90% 는 모델 실행 전에 사용자가 정한 값이다. B 는 실제 서류를 채점하면서 작은 서류가 2장뿐이라는
사실이 드러나 추가한 관점이며, 판정 기준이 아니라 해석을 위한 보조 지표다. C 의 수작업 시간은 사용자의
평소 작업 시간을 물어서 얻었다.

### 도입 조건 (점수와 별개)

- **고객 서류를 외부 서버로 보내지 않는다.** 업무가 끝난 서류라도 고객 개인정보가 담겨 있다.
  → 모델은 내 PC 에서 돌아가야 한다. 외부 API(GPT·Gemini 이미지 분류)는 제외했다.
- **실제 서류는 GitHub 에 올리지 않는다.** 제출용 샘플은 실제 서류의 구성을 본떠 만든 가짜 서류다.

## 7. 이 PoC 에서 하지 않는 것

- **개인정보 마스킹** — 블로그에 올리려면 이름·학교명·점수 등을 가려야 한다. 실제 업무에서 가장 큰 이득이
  있는 단계지만 과제 기간 안에 끝낼 수 없어 다음 단계로 넘긴다 (→ [`04_limits_next.md`](04_limits_next.md))
- 작은 서류만 잘라내기 — 사용자가 A4 페이지째 저장을 원했다 (R4)
- 서류 종류 분류(졸업장/증명서/여권), 웹앱·배포
